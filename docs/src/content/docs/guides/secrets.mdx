Deploy sensitive files and directories to your machines with explicit ownership and permissions, accumulated down the fleet hierarchy.

The secrets phase transfers plain files and directories via `rsync`. Every field (paths, ownership, permissions) is configured per secret entry.

## Inheritance

Secrets defined at the fleet, flake, and installable levels **append** down to machines. They are never replaced, only accumulated:

```yaml
fleet:
  secrets:                              # Inherited by all machines
    - local_path: ./secrets/common.key
      remote_path: /var/secrets/common.key
      permissions: 0600                # File permissions (default: 0700)

  flakes:
    my-flake:
      secrets:                         # APPENDED to inherited secrets
        - local_path: ./secrets/api.key
          remote_path: /var/secrets/api.key

      installables:
        nixosConfigurations:
          webserver:
            machines:
              web-01:
                secrets:                  # Further appended secrets
                  - local_path: ./secrets/web-01/cert.pem
                    remote_path: /etc/ssl/cert.pem
                    uid: 1000            # User ID (when unset, ownership is whatever the receiving rsync runs as)
                    gid: 1000            # Group ID (when unset, ownership is whatever the receiving rsync runs as)
                    permissions: 0644
```

## Secret Fields

| Field | Description |
|-------|-------------|
| `local_path` / `remote_path` | Source and destination. Pointing `local_path` at a directory transfers the entire directory. |
| `uid` / `gid` | Remote file ownership (must be set together). When unset, ownership is whatever the receiving rsync runs as (the SSH user when it is root, otherwise root via sudo). |
| `permissions` | Octal file permissions (e.g. `0600`, `0644`). Default: `0700`. |

## When Secrets Are Transferred

Regular secrets are transferred during the Secrets phase (after Transfer, before Activate).

To update secrets without a full deploy, run `panix secrets`: it executes only the Inspect and Secrets phases (no build, transfer, or activation).

Disk encryption keys are transferred during Bootstrap, **before** `disko` runs, so they are available for disk encryption setup. See the [Bootstrap guide](/guides/bootstrap/) for where they fit in the flow.

## Security

Secrets are transferred directly to the target machine via `rsync` and are never committed to the Nix store. You can safely deploy unencrypted secrets without them being stored in `/nix/store` (world-readable by default).

Secrets reach the correct path whether targeting a running NixOS system or a bootstrapped machine: during bootstrap the target root is mounted at `/mnt`, so Panix automatically prefixes paths (e.g. `/var/secrets/key` becomes `/mnt/var/secrets/key`).
