Panix supports two build modes: **local** (default) and **remote**. This controls where the Nix closure is built.

## Local Mode (Default)

Builds run on the machine executing Panix:

```sh
nix build --no-link --print-out-paths --keep-going <flake-url>#<installable>
```

This command is abbreviated: Panix also passes the experimental features flags (`--extra-experimental-features nix-command flakes`) and any configured default and extra build flags (see [Nix Command Flags](./nix-flags.mdx)). The same applies to the remote build command below.

The resulting closure is then transferred to each target machine via `nix copy`.

## Remote Mode

Builds run on the installable's first machine via the Nix remote store protocol:

```sh
nix build --eval-store auto --store ssh-ng://<first-machine> --option builders "" --no-link --print-out-paths --keep-going <flake-url>#<installable>
```

This is useful when the target machine has more resources (CPU/RAM) than the deployment machine, or when deployment and target machine are not the same architecture.

:::note
For installables with multiple machines, the closure is built on the first machine, then copied from it to the remaining machines via `nix copy --from ssh-ng://<first-machine> --to ssh-ng://<other-machine>`. Single-machine installables in remote mode skip the transfer phase entirely since the closure is already on the target.
:::

:::note
**Requirements:**

- The first machine must be **remote** (not the local machine running Panix)
- The first machine must have Nix installed and the flake inputs available
- If the first machine is bootstrapped in the same run, remote builds may target its temporary installer environment, whose store is discarded on reboot; builds or copies racing that reboot can fail and need a retry (or a restart, for non-installed artifacts like the disko script). Prefer an already-provisioned first machine, or bootstrap it in a separate run.
:::

**Configuration:**

```yaml
fleet:
  flakes:
    my-flake:
      url: <url>
      installables:
        nixosConfigurations:
          my-server:
            nix:
              build_mode: remote          # Build remotely instead of locally
            machines:
              builder-and-target:         # First machine: remote builder and target
                ssh:
                  hostname: 192.168.1.100
              target-2:                   # Closure copied from builder-and-target to target-2
                ssh:
                  hostname: 192.168.1.101
```

`build_mode` can be set at fleet, flake, or installable level (inherited like other `nix` options). It cannot be set at machine level, as an installable's machines share the same build mode (since build is a per-installable phase).

## Advanced Distributed Builds

For more advanced remote/distributed builds, you can use additional `nix` command flags or set it up in your NixOS config.

Some documentation is available at:

- [Distributed build: NixOS Wiki](https://wiki.nixos.org/wiki/Distributed_build)
