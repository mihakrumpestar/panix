## Unit Tests

```sh
task go:test
```

## Benchmarks

A custom benchmark comparison tool (`tests/bench/`) discovers, runs, and renders Go benchmarks with multi-variant comparison.

```sh
task go:test:bench
```

Filter to specific packages:

```sh
task go:test:bench -- ./pkg/tui/...
```

Adjust per-benchmark duration:

```sh
task go:test:bench -- -benchtime=5s
```

**Naming convention**: benchmarks use `Benchmark_<Variant>__<Feature>`. The `__` separator splits variant from feature name. All benchmarks sharing the same feature are grouped for comparison. An unnamed/baseline variant uses `Benchmark__<Feature>`.

**Output**: one table per package. Each cell shows time, bytes/allocs, and ratio vs the best variant. Columns are sorted by overall cumulative performance (ratio-based scoring). Example:

```
BufferWrite/ASCII        668 ns (0 B, 0 allocs)              | best (baseline)
BufferWrite/ASCII        685 ns (0 B, 0 allocs) +1.03×       | 1.03x slower
```

Cross-package benchmarks live in `tests/bench/`:
- `tests/bench/buffer/`: 16+ buffer implementation variants compared
- `tests/bench/tui/`: full TUI pipeline, zeroterm vs Bubbletea vs cview

## E2E Tests

End-to-end tests run the full deployment pipeline against real QEMU VMs:

- **Bootstrap**: NixOS installed from the ISO installer, and Debian converted via kexec, in both local and remote build modes
- **Redeploy**: a second deploy against the installed systems, covering all installable types (NixOS, home-manager, packages, maid, system-manager) plus an auto-rollback test
- **Verification**: each VM is checked for the `panix-e2e-test-pass` marker file and NixOS identity in `/etc/os-release`

**Prerequisites**: KVM (`/dev/kvm`), QEMU, Nix, harmonia

```sh
task go:test:e2e                          # Both build modes (5 VMs, default)
task go:test:e2e -- --test=local          # Only local build mode (3 VMs)
task go:test:e2e -- --test=remote         # Only remote build mode (2 VMs)
```

A full run takes ~3 minutes. The suite is a standalone Go program (`go run ./tests/e2e/`), not `go test`; set `PANIX_BIN=/path/to/panix` to test a pre-built binary.

Expensive setup (baked Debian images, disk images, installer ISO, kexec tarball) is cached across runs, and a local harmonia cache server starts automatically so deploy builds do not hit the network. Logs are recreated each run in `tests/e2e/log/` (per-VM console logs, panix logs, snapshot JSONs).

### E2E Profiling

The E2E panix config enables profiling during the bootstrap phase. Profiles are written to `tests/e2e/profile/`:

```sh
task go:profile:report          # CPU + memory (top 50, self time)
task go:profile:report:cum      # CPU + memory (top 50, cumulative)
task go:profile:report -- /path/to/profile/dir   # custom profile dir
```

Panix supports CPU, memory, block, mutex, and goroutine profiling via the `profile.*` flags in `panix.yml`.

### E2E Benchmarks

Cross-commit performance benchmarking. Builds panix at specific commits, runs E2E, and compares profiles.

```sh
task bench:e2e                          # Run all default phase commits (RUNS=1 by default), then generate graphs and summary table
task bench:e2e COMMITS="sha1 sha2"      # Custom commit list
task bench:e2e:run COMMIT=sha           # Build & run E2E for a single commit
task bench:e2e:graph                    # Generate comparison graphs and summary table from saved profiles
```

`bench:e2e:run` creates a git worktree, builds panix via `nix build`, runs the full E2E suite, and saves CPU/memory profiles to `tests/e2e/bench-results/run-<N>/<full-sha>/`.

`bench:e2e:graph` extracts duration, CPU utilization, and memory allocation from each commit's profiles, prints a comparison table with diffs from the reference commit, and generates comparison graphs.

:::note
Benchmarks were not updated since the last mayor Panix optimizations, and will probably not be updated to accommodate the breaking changes (nixosConfigurations -> installables).
:::
